    LinkedQueue

    Data Structure

    A LinkedQueue stores elements using a First-In-First-Out (FIFO) policy. Elements are enqueued at the rear and dequeued from the front.

    This is a Java-style reference/object visualization: a field or local variable contains a reference to an object, or null. The queue object stores first, a reference to the front node object; last, a reference to the rear node object; and size, the number of stored elements.

    Each node object has an element field and a next field. Because the structure is generic, node.element is a reference to a value object, not necessarily a primitive stored inside the node.

    An object is reachable if it can be reached by following references from active variables or fields. When no active reference can reach a node object, it is an unreachable object and the Java garbage collector may eventually reclaim it.

    Operations & Complexity

    • Enqueue: Creates a node object with next = null. If the queue is empty, both first and last reference it; otherwise, last.next and then last are updated — O(1)
    • Dequeue: Removes the front node by updating first to the next node. If the queue becomes empty, last is set to null. The removed node becomes unreachable from the queue and may later be reclaimed by Java's garbage collector — O(1)
    • First: Reads and returns the element reference stored in the front node without removing it — O(1)
    • Clear / Empty: Sets first and last to null, then sets size to 0. The former node chain becomes unreachable from the queue and may later be reclaimed by Java's garbage collector — O(1)
