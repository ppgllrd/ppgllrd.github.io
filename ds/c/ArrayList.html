ArrayList

1. Data structure

An ArrayList stores a logical sequence inside a contiguous heap-allocated array. The list object keeps three fields: a pointer/reference to the physical array, the current capacity of that array, and the logical size of the list.

Cells with indexes smaller than size are logical elements of the list. Cells from size up to capacity - 1 are allocated but outside the logical list. They may still contain old physical values, but those values are not part of the list.

2. Visual memory and reference model

  • Green cells represent logical elements, the capacity field, or the size field.
  • Yellow cells represent allocated array cells that are currently outside the logical size.
  • Cyan cells represent pointer/reference fields or temporary references to array cells.
  • Purple cells represent the pointer/reference to the ArrayList object itself.
  • Arrows show references from the list object or temporary variables to the heap-allocated array or to a selected array cell.

3. C-style memory concepts

A pointer variable stores an address/reference. The ArrayList object stores the array pointer plus metadata. The array object is a heap block containing the physical cells. Updating a pointer changes what it refers to; it does not copy the array by itself.

The list object and the backing array live on the heap after allocation. Temporary variables used by operations are local variables; they disappear when the operation returns. Local variables going out of scope does not free heap memory unless the algorithm explicitly frees or replaces a heap object.

NULL means “points to no object.” A dangling pointer is a pointer that still stores the address of memory that has already been freed. During resizing, the old array must not be used after the ArrayList starts referring to the new array and the old heap block is released.

Allocation creates a new heap array or list object. Freeing releases a heap object. Reallocation/resizing allocates a larger array, copies existing logical elements into it, updates the list's array pointer, and releases the old array.

4. "Visualization only" messages

Status messages beginning with "Visualization only:" describe drawing, layout, animation, sample data, view movement, or interface behavior. They are not conceptual data-structure actions. Messages without that prefix describe real algorithmic actions such as allocation, traversal/copying, comparison, index access, pointer/reference updates, freeing/reallocation, value replacement, size updates, or setting a pointer/reference to NULL.

5. Real data-structure operations

  • New: allocates a new empty ArrayList with the chosen initial capacity. Purpose: start with size 0 and an allocated backing array. Complexity: O(1) for the metadata, plus allocation cost for the array block.
  • Append: ensures there is capacity, writes the value at the current size index, then increments size. Purpose: add a value at the end. Complexity: amortized O(1); worst-case O(n) when resizing copies existing elements.
  • Prepend: inserts at index 0 by shifting all current elements one position right, storing the new value, and incrementing size. Purpose: add a value at the beginning. Complexity: O(n).
  • Insert: shifts elements from the insertion index to the end one position right, stores the new value, and increments size. Purpose: add a value at any valid position. Complexity: O(n) in general; O(1) at the end when no resize is needed.
  • Get: directly accesses the array cell at the selected index. Purpose: read a value. Complexity: O(1).
  • Set: directly accesses the selected index and overwrites that value. Purpose: update a stored value without changing size or capacity. Complexity: O(1).
  • Delete: removes the selected logical element, shifts following elements one position left, and decrements size. Purpose: remove one value while preserving order. Complexity: O(n) in general; O(1) when deleting the last element.
  • Clear: sets size to 0 while keeping the allocated backing array and capacity. Purpose: make the list logically empty without releasing the array. Complexity: O(1).
  • Ensure capacity / resize: allocates a larger backing array, copies existing logical elements, updates the array pointer/reference, and releases the old array. Purpose: make room for future insertions. Complexity: O(n) for that resizing step.

Build Random, Undo, visual demos, and sample generation are interface utilities, not ArrayList operations.
